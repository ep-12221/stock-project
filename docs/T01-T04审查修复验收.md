## 1. 修复结果

| 审查发现 | 修复后的行为 | 主要入口 |
| --- | --- | --- |
| 并发登录/注册的迟到响应覆盖 Cookie，页面与服务端身份不一致 | Pinia 中登录、注册、退出共用互斥操作；第二个操作在发送 HTTP 前被拒绝，当前操作结束后可正常重试。认证页面同步禁用表单、切换链接和离开页面的路由导航 | apps/client/src/stores/auth.ts、router/index.ts、views/AuthView.vue |
| ENABLE_DEMO_LIQUIDITY=false 无效 | 严格解析 true/false，默认 true；false 时启动不提交六张种子单，初始市场版本为 0，最佳买卖价均为 null，系统库存仍保留 | apps/server/src/config.ts、index.ts、.env.example |
| 不支持的 JSON 字符集或内容编码返回 500 | 返回 415 / UNSUPPORTED_MEDIA_TYPE，保留请求 ID，不改变交易或账户状态 | apps/server/src/middleware/error.ts |
| 清仓后显示仍持有股票 | 首页只统计 quantity>0 的持仓；全部冻结但数量大于 0 的股票仍计入持有数 | apps/client/src/views/HomeView.vue |

身份操作还覆盖了两项相关失败边界：退出期间会话过期也能解除 busy；加载账户与行情的任一请求失败时，等待两个请求全部结束才解除互斥。认证期间主动恢复身份会等待当前操作，不额外发起身份查询。

本轮没有修改撮合排序、资金结算、交易分页、系统库存发行或公共 DTO 字段。交易页面、WebSocket、幂等和撤单仍按原阶段规划实施。

## 4. 真实 HTTP 与生产构建复验

- 使用现有 Pinia 状态实现、真实后端 HTTP 接口与 Cookie 容器，延迟 alice 的注册请求，同时尝试登录 bravo。并发登录被拒绝，服务端没有收到该登录请求；注册结束后页面与服务端均为 alice。随后顺序登录 bravo，页面、账户快照与服务端身份仍一致。
- 生产构建显式开启种子挂单后，scripts/verify-trading.mjs 原验收脚本通过：两个独立会话、三笔成交、部分成交、失败原子性、分页、脱敏和静态入口均正常。最终 A 现金 99,939,900 分、60 股全部冻结；B 现金 99,909,950 分、90 股。
- 生产构建显式关闭种子挂单后，初始 marketVersion=0，三只股票的最佳买卖价全部为 null。
- 在生产开关的两种配置下，非法字符集与内容编码均返回 415 / UNSUPPORTED_MEDIA_TYPE，请求前后的账户快照完全相同。

上述身份检查使用真实 HTTP 和 Cookie 容器，但不是完整浏览器端到端测试；认证页面及清仓展示由 Vue 组件和路由测试验证。
