# 双账户交易演示

以下流程从默认流动性开启的新服务开始，使用普通窗口与无痕窗口隔离 Cookie：

1. 分别注册 alice、bravo，确认各有 100 万虚拟币且暂无持仓。
2. alice 选择 SIM001，按最佳卖价 10.01 买入 100 股，确认“全部成交”、持仓 100、可用资金 998,999.00。
3. alice 切换卖出，以 11.01 提交 60 股，确认“已挂单”，持仓中冻结 60 股。
4. bravo 以 11.01 买入 1,000 股：先吃掉系统剩余 900 股，再撮合 alice 的 60 股，显示“部分成交”960/1,000，冻结资金 440.40。
5. alice 无需操作即可看到可用资金变为 999,659.60、剩余 40 股、卖单全部成交；以 11.01 卖出这 40 股，确认清仓且资金为 1,000,100.00。
6. bravo 无需刷新即可看到买单全部成交、持仓 1,000 股、冻结资金归零、可用资金 989,890.00。
7. 在“我的委托”筛选已成交，在“我的成交”和“市场成交”核对记录；市场视图不显示用户身份或买卖方向。
8. 刷新浏览器，确认登录与资产恢复；退出 alice，确认 bravo 的独立会话仍有效。重新登录 alice 不会重复发放资金。
9. 输入多于两位小数的价格、小数股数、超过可用资金 / 持仓的委托，确认表单阻止提交且资产不变。
10. 在开发者工具切换离线，等待断线提示（静默断网最迟约 15 秒检测）；确认资产和输入保留、下单暂停。恢复网络后自动重连，或点击“重新连接”，等待完整快照后继续交易。
11. 重启后端，确认旧身份失效并返回登录，数据清空。

下单请求超时或返回 5xx 时，页面显示原股票、方向、限价和数量，并暂停新下单。恢复连接后点击“重试并确认此委托”：如果原委托已受理，返回该订单当前状态；如果尚未受理，本次会提交。即使账户已经通过实时推送更新，也须确认原请求后才能继续。

原请求会在发送前写入当前标签页的 sessionStorage，刷新后仅恢复待确认提示，不自动 POST。同一用户重新登录可恢复，同一页面切换用户或服务重启后不会混用。关闭标签页、清除浏览器存储或换设备后不保证恢复该请求标识，请先核对历史委托；新请求标识代表另一笔委托。浏览器存储不可用时暂停下单；请通过 localhost 或 HTTPS 访问，以使用安全的请求标识生成能力。详情见 [T07 幂等与稳定性验收](幂等与稳定性实现验收.md)。

系统额外初始化一个不可登录的 system 账户，现金同样为 100 万，每只股票持有 10,000 股。默认启动通过撮合服务为每只股票提交 1,000 股种子买单和卖单，价格分别为初始价减 1 分和加 1 分；库存或挂单耗尽后不会自动补充。设置 ENABLE_DEMO_LIQUIDITY=false 后重启，可关闭种子挂单；系统初始库存仍保留。直接创建测试内存时订单簿保持为空。

撮合核心可单独验收：

```bash
npm test -- apps/server/src/tests/trading
```

交易接口包括 `POST /api/orders`、`GET /api/me/orders`、`GET /api/me/trades` 和 `GET /api/trades`。下单必须包含 UUID 格式的 clientOrderId，以及 symbol、side、priceCents、quantity；userId 只取自服务端会话。首次成功返回 201，同用户同标识同参数重放返回 200，标识相同但参数不同返回 409 / IDEMPOTENCY_CONFLICT。查询默认 50 条、最多 100 条，使用服务端序号游标。基础接口验收见 [交易 API 验收记录](交易API实现验收.md)，当前幂等契约以 [T07 验收文档](幂等与稳定性实现验收.md)为准。
