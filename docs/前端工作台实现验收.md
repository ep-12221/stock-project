日期：2026-09-05。前置基线：T01～T04 审查修复后 292 个测试通过。本阶段保留后端 API 和撮合规则，接入可操作的交易页面。

## 实现范围

| 区域 | 已实现行为 |
| --- | --- |
| 账户概览 | 可用现金、冻结现金、持仓市值、总资产；冻结现金及股数不重复计入；清仓显示暂无持仓 |
| 股票行情 | 服务端股票、模拟最新价、正负涨跌幅、最佳买卖价、更新时间；点击选择股票 |
| 限价委托 | 买入 / 卖出切换；显式使用最佳对手价；整数分和整数股校验；可用余额 / 可卖持仓校验；防重复点击 |
| 下单结果 | 根据 OPEN / PARTIALLY_FILLED / FILLED 显示已挂单 / 部分成交 / 全部成交，服务端快照更新资金、持仓及订单 |
| 持仓 | 股票、总量、可用量、冻结量、模拟最新价和市值；无持仓空态 |
| 历史记录 | 本人委托、个人成交、匿名市场成交；股票 / 委托状态筛选；每页 50 条、游标追加、按 ID 去重；加载与重试状态 |
| 身份与异常 | 登录过期跳转；旧身份 / 旧查询结果丢弃；409 刷新余额；网络异常和 5xx 核对后才能继续交易 |
| 适配 | 桌面行情 / 表单 / 持仓布局；小屏纵排，表格局部横向滚动 |

前端没有提前扣款、增加股数或生成成交。价格输入先按整数部分及小数部分转换为分，金额累计使用 BigInt。更新行情不会覆盖已编辑价格；切换股票时才重新初始化价格。

## 状态与一致性

- accountStore 的 applySnapshot 验证账户身份、服务实例及 accountVersion，原子替换整个账户快照；marketStore 以相同方式管理市场实例与 marketVersion。
- 账户首次版本 0 可应用；已应用的同版本和旧版本不会覆盖当前状态。登录恢复、手动刷新、下单响应复用这些入口，供 T06 推送继续接入。
- tradingStore 为请求捕获用户、服务实例和登录操作代次，避免迟到响应写入另一个会话；每类历史查询另有请求代次，快速切换筛选时只应用当前结果。
- 刷新同一用户不会重置交易状态；退出请求失败时保留已有历史和未知订单的核对要求。
- 下单超时或 5xx 后保留输入，禁止自动重发；用户需刷新账户，在全部股票 / 全部状态的委托列表核对，再手动继续。列表查询失败或仍被筛选时，不开放核对确认。
- 幂等及跨页面的重复下单保证属于 T07；目前的核对流程不能代替服务端幂等。

## 真实浏览器验收

使用生产构建、隔离端口上的真实后端和本地无头 Chrome，通过 Playwright 驱动页面。两个 BrowserContext 分别注册独立用户，全部买卖操作从页面提交，账户读取用于交叉核对。内置 Browser 插件的 Node 内核因 Windows 沙箱初始化失败不可用，因此改用本机独立浏览器；未修改项目依赖。

### 默认种子流动性

1. A、B 各注册取得 1,000,000.00，空持仓。
2. A 以 10.01 买入 SIM001 100 股，全部成交；资金 998,999.00，持仓 100。
3. A 以 11.01 卖出 60 股，挂单成功；冻结 60 股。
4. B 以 11.01 买入 1,000 股，先成交系统 900 股，再成交 A 的 60 股；页面显示部分成交 960/1,000，冻结资金 440.40。
5. A 刷新后持仓 40，再以 11.01 卖出 40 股；清仓，资金 1,000,100.00。
6. B 刷新后买单全部成交，持仓 1,000、冻结资金 0、资金 989,890.00。
7. 本人委托已成交筛选、个人 3 条成交、市场 4 条匿名成交均正确；市场表不显示方向及用户身份。
8. 切换股票联动限价；浏览器重新加载恢复资产；A 退出后 B 的会话仍有效。
9. 截取 1440px 桌面和 390px 手机页面并审视；手机整页没有横向溢出，表格独立滚动，浏览器 pageerror 为 0。

### 无对手盘与故障反馈

另启 `ENABLE_DEMO_LIQUIDITY=false` 的隔离服务：

- 页面显示暂无对手盘，“使用最佳价格”禁用；10.00 买入 5 股正确挂单，冻结 50.00。
- 浏览器拦截历史请求模拟 500，展示重试提示；恢复网络并刷新后恢复列表。
- 拦截下单模拟网络失败，提交按钮保持禁用；先刷新并核对，再手动继续；未自动再次发送 POST，历史仍只有原有一单。
- 下单返回 401 后清空私有页面并跳转登录页。
