# 关键 Prompt 记录

这里选了开发过程中四个比较具体的问题。Prompt 按当时的上下文做了改写，后续处理对应项目中的实际修改和测试。

## 1. 后端写完后，先检查一遍

当时后端已经做到 T04，账户、撮合和交易接口都有了。接前端之前，先检查已有代码，避免后面调页面时再追查后端问题。

> 后端已经做到 T04 了。你先看 docs 里的题目和实现文档，再对照代码查一下。撮合和资金计算多留意一下，特别是部分成交以后，钱和股票的数量能不能对上。登录注册、配置开关这些也检查一下。有问题把触发方式和对应代码列出来，先给我看结果。

检查发现了并发登录响应可能影响 Cookie、关闭系统挂单的配置未生效、部分请求错误返回 500，以及清仓后仍统计空持仓等问题。后续先处理这些问题，再继续接前端。[修复记录](T01-T04审查修复验收.md)

## 2. 修问题前，先让测试报错

上一次已经有了问题清单。这一步需要确认修复确实覆盖了原来的问题，尤其是登录请求顺序变化时的表现。

> 先把刚才查出来的几个问题修了。每个问题先补一个能复现的测试，看到测试失败再改代码。登录注册那个多试一下，比如先发的请求反而后回来，或者两个请求里有一个失败。改完把原有测试也跑一遍，看看有没有影响别的地方。

这一轮先补回归，再修改身份操作锁、配置解析、错误处理和持仓统计。复查时又发现，一个并行请求失败后可能提前释放认证锁，也补了用例处理。最终增加 31 项测试，连同原有测试一起通过后，再进入前端阶段。[测试和修复结果](T01-T04审查修复验收.md)

## 3. 接前端时，把失败的情况一起考虑

后端接口能用了，需要在页面上完成买入、卖出和查看记录。除了正常交易，也要让用户看得懂加载、失败和未成交这些状态。

> 接下来把交易接口接到前端。我想在一个页面里看到行情、余额、持仓和自己的委托，选一只股票就能填价格和数量买卖。下单的时候按钮先禁用，别让用户连点。请求失败后保留输入，余额和持仓等后端结果回来再更新。做完用两个账户试一下买入、挂卖和部分成交，手机上也看一下能不能正常操作。

前端接上了账户概览、交易表单和历史列表。实现中加入版本和请求顺序检查，避免切换股票或筛选记录时被旧响应覆盖；对下单结果不明的情况保留待确认状态。复查又修了退出失败时清空历史的问题，并用两个独立浏览器会话走通交易流程。这一阶段之后，再补上 WebSocket 实时同步。[前端验收](前端工作台实现验收.md)

## 4. 处理“已经成交，但页面没收到结果”

正常交易和实时更新都完成后，还需要处理网络异常。只禁用按钮无法解决请求发出后超时、用户再次提交的问题。

> 还有个情况：后台已经成交了，但页面没收到响应，用户再点一次就可能多买一笔。给同一笔请求加个能识别的编号，重试时沿用它，后端查到处理过就返回原来的订单。刷新页面以后也要能找回这笔待确认委托，让用户确认。把响应丢失和等响应时刷新这两种情况都试一下，看订单数和余额有没有多变一次。

后端增加了 `clientOrderId`，按用户识别重复请求；前端在发送前保存原委托，刷新后也能继续确认。测试时先创建订单，再并发重放 8 次，始终只有原来那张订单。浏览器里也验证了成交后响应丢失、等待响应时刷新，两种情况都能返回原订单，没有重复扣款或成交。[幂等与恢复验收](幂等与稳定性实现验收.md)
