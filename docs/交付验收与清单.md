## 2. 通用启动与演示

将源码包解压到新目录，进入顶层 stock-project。要求 Node.js 22.14+（22.x）或 24.x、npm 10+；本次在 WSL Ubuntu / Node 22.14.0 / npm 10.9.2 验证。

```bash
cd stock-project
npm ci
npm run dev
```

浏览器打开 http://localhost:5173/register，注册后进入工作台。一个命令同时启动前后端，Ctrl+C 停止。使用普通窗口和无痕窗口作为两个不同用户，按 [README 功能验收](../README.md#功能验收)完成买入、挂卖、部分成交及全部成交；普通窗口的两个标签页通常共享 Cookie，不能当作两个独立用户。

生产运行：

```bash
npm run build
npm start
```

打开 http://localhost:3000；只需后端进程即可提供页面、REST 和 WebSocket。若开发后端正在使用 3000，应先停止它，或在独立终端配置其他 PORT。

系统状态全部在内存，重启后用户、会话、订单和成交清空。有限系统挂单不自动补充，随机行情不驱动虚构成交。原请求确认依靠同一个 clientOrderId；关闭标签页或清空浏览器存储后不要把新的请求标识当作原单重试。

## 4. Docker 配置与实际验收

新增 [Dockerfile](../Dockerfile)、[docker-compose.yml](../docker-compose.yml) 和 [.dockerignore](../.dockerignore)。

Dockerfile 包含构建、生产依赖及最终运行阶段，按锁文件安装和构建；运行镜像只复制 Node 生产依赖、server/shared 实体产物和 client 静态文件，以非 root 的 node 用户直接执行 Node 入口。没有把主机 .env、node_modules 或旧 dist 拷入构建。健康检查使用容器内 `/api/health`，SIGTERM 直接交给 Node，Compose 停止宽限为 15 秒。

Compose 容器固定监听 0.0.0.0:3000，默认映射宿主机 127.0.0.1:3000。APP_PORT 可以更改宿主端口，允许的 localhost / 127.0.0.1 Origin 同步更改。容器 NODE_ENV / HOST / PORT 显式设置，根 .env 的开发配置不会将它误改为只监听容器内部回环地址。

先确认缺少 Compose 文件时配置命令失败，再创建配置。实际 Docker CLI 已解析并检查三种配置：默认值、自定义 APP_PORT=4350（包括不泄漏开发配置）、自定义 HTTPS 来源与 Cookie / 流动性配置。相关文件的格式检查通过。

初次构建因 Docker Desktop 引擎未启动而无法连接。随后启动本机已安装的 Docker Desktop，使用 Windows Docker CLI 完成实际构建与验收，没有安装组件或修改 WSL 集成配置。首次无缓存拉取 Docker Hub 基础镜像耗时较长，成功后继续完成 npm 安装和应用构建；不能将前文使用 npm 缓存的耗时套用到首次镜像下载。

实际环境为 Docker Engine 29.1.3、Compose 2.40.3、容器 Node 22.23.2。独立项目名 stock-t08-check，宿主端口 4350，验证结果如下：

| 检查 | 实际结果 |
| --- | --- |
| 多阶段构建与启动 | compose up --build -d --wait 成功，容器 healthy |
| 最终运行镜像 | UID 1000、Node 为 PID 1；无 .env、源码、Vue / Vite / tsx / TypeScript；共享包可导入，前端 dist 完整 |
| 静态入口与交易 | verify-trading.mjs 原脚本通过，包含双用户成交、部分成交、冻结、失败原子性、分页与会话隔离 |
| WebSocket 鉴权 | 无 Cookie 返回 401，错误 Origin 返回 403，有效会话收到本人首帧 |
| WebSocket 实时链路 | 后续行情版本递增，真实成交触发私人账户推送，同键请求返回 200 重放 |
| 正常停止 | compose stop 后 WebSocket 收到 1001，Node 正常退出，容器 ExitCode=0 |
| 关闭系统挂单后的幂等 | 同一项目重建为 ENABLE_DEMO_LIQUIDITY=false，verify-idempotency.mjs 八路并发重放、单次落单、冲突无副作用、用户隔离、UUID 大小写与缺失 / 非法标识验收通过 |

最后执行本项目的 compose down --rmi local，移除验收创建的容器、网络及应用镜像；按项目标签查询为空，4350 已关闭。原 3000 后端健康检查和 5173 页面仍返回 200。Docker Desktop 引擎保留运行，未操作其他项目容器。

可在新建的验收项目中复验。以下为 Bash 命令，4350 用来避开开发端口：

```bash
APP_PORT=4350 docker compose -p stock-t08-check up --build -d --wait
node scripts/verify-trading.mjs http://127.0.0.1:4350
APP_PORT=4350 docker compose -p stock-t08-check down

ENABLE_DEMO_LIQUIDITY=false APP_PORT=4350 docker compose -p stock-t08-check up -d --wait
node scripts/verify-idempotency.mjs http://127.0.0.1:4350
APP_PORT=4350 docker compose -p stock-t08-check down
```

PowerShell 应先设置 `$env:APP_PORT='4350'`，关闭系统挂单时另设 `$env:ENABLE_DEMO_LIQUIDITY='false'`，再执行相应 Compose 命令。默认种子交易脚本要求全新启用种子的实例，幂等脚本要求全新关闭种子的实例；进程重启会清空本实例内存数据。
