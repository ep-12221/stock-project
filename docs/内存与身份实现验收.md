## 1. 实现范围

- 每个应用实例独立的用户、用户名索引、账户、持仓、股票与会话 Map。
- 三只股票的初始参考行情；不可登录的系统账户及初始库存；种子初始化可重复调用且不会补发资产。
- 注册、登录、退出、当前身份查询；注册自动登录，登录不再次发放初始资金。
- 用户名去除两端空白并转为小写；用户名 3～20 位，密码 8～64 字符；密码中的空白保留。
- 随机盐 + 异步 scrypt 摘要、恒定时间摘要比较；HttpOnly / SameSite=Lax / 可配置 Secure Cookie。
- 固定到期会话、当前会话撤销、定期清理；系统用户无法创建会话。
- 身份、账户、持仓、快照和股票查询均鉴权，私有查询不缓存。
- 前端登录注册表单、确认密码、重复提交保护、错误反馈、路由保护、刷新恢复、过期清理、账户概览和退出。

不包含撮合、种子挂单、实时行情、WebSocket 服务和交易操作。订单及成交快照字段当前为空，后续将连接真实交易索引。

## 5. 生产构建的真实 HTTP 验收

用 npm start 在独立端口 3002 启动编译产物，使用两个独立 Cookie 会话完成：

| 操作 | 结果 |
| --- | --- |
| 打开 /login | 200，前端静态入口可用 |
| 未登录查询账户 | 401 |
| 分别注册两个用户 | 两次 201 |
| 查询初始快照 | 可用资金 100,000,000 分，持仓为空 |
| 查询股票 | 3 只 |
| A 查询时传入 B 的 userId | 仍返回 A 的快照 |
| A 退出 | 204 |
| A 再查询身份 | 401 |
| B 的独立会话继续查询 | 200 |
| A 重新登录 | 200，资金没有重复发放 |

该端口仅用于验收，结束后停止。重启清空和过期边界另外由独立存储与可控时钟的测试覆盖，不依赖长时间等待。

## 6. 关键设计与后续衔接

- 账户快照新增 userId，客户端同时检查 userId 和 serverEpoch，避免组合不同身份或不同服务实例的响应。
- 旧异步请求使用本地代次隔离，不能在退出后重新覆盖私有状态。
- 每个会话单独撤销；登录成功替换浏览器原会话，失败登录保留原会话。
- API 请求来源白名单显式配置；注册与登录必须是 JSON，退出可不带请求体。
- 程序入口负责每分钟清理过期会话，停止进程时清理计时器；请求鉴权按精确到期时间判断。
- 系统库存为将来的种子挂单提供来源；T03/T04 接入时必须通过正常冻结与撮合流程，不能直接伪造成交。
- 本阶段前端自动验收使用 DOM 环境；真实浏览器视觉与完整端到端自动化没有在本记录中声称已完成。

后续所有新增功能继续执行“先写测试并观察失败 → 实现 → 测试验收”的顺序。
