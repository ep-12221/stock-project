# 股票模拟交易系统

已完成 **T01 工程骨架**、**T02 内存与身份**、**T03 撮合核心**、**T04 交易 API**、**T05 前端工作台**、**T06 实时链路**、**T07 幂等与故障恢复**，以及 **T08 本地交付整理**。

- 注册、登录、退出，以及刷新页面后的登录态恢复；同一页面会话中的身份操作互斥，防止并发响应覆盖 Cookie。
- 每位新用户获得 1,000,000 虚拟币，初始持仓为空；登录不会重复发放资金。
- 密码使用随机盐和异步 scrypt 摘要，会话保存在服务端内存，浏览器使用 HttpOnly Cookie。
- 工作台展示三只股票的模拟最新价、最佳买卖价、可用及冻结资金、持仓市值和总资产；服务端每秒统一更新模拟行情。
- 点击股票提交限价买入或卖出；根据服务端结果显示已挂单、部分成交或全部成交，更新资金与持仓。
- 双方成交后，资金、持仓、委托和成交记录通过 WebSocket 自动更新，无需刷新。
- 查看本人委托、个人成交和匿名市场成交，支持股票 / 委托状态筛选、游标分页和实时记录合并。
- 断线时保留资产与输入、暂停下单；自动重连后获取完整快照，再恢复交易。
- 每笔下单携带唯一请求标识；超时后用原委托重试，只返回原订单的最新状态，不重复冻结或成交。
- 当前标签页刷新后可恢复待确认委托，由用户点击确认，不会自动重新下单。
- 会话过期、退出或服务重启后，旧身份失效；前端清理可见私有状态并返回登录页。

撮合核心支持价格优先、时间优先、部分成交、现金与持仓冻结、价差释放、自成交防护及原子结算；下单、本人委托、个人成交和匿名市场成交 API 已接入，支持严格筛选及游标分页。启动时每只股票有有限的真实买卖种子挂单。

页面已可完成买入与卖出。正常行情与交易同步由 WebSocket 驱动，没有定时 HTTP 轮询；手动刷新保留为账户核对入口。模拟最新价独立波动，成交仍由真实限价挂单撮合，行情变化不会凭空产生交易。所有业务状态均在单个后端进程内存中，**重启后全部清空**。

## 环境与启动

使用 Node.js **22.14+（22.x）或 24.x**、npm 10+。当前在 WSL Ubuntu、Node.js 22.14.0、npm 10.9.2 下验证；.nvmrc 固定本次版本，已安装 nvm 时可运行 nvm use。

进入源码目录后执行（WSL / macOS / Linux 终端，或已安装 Node.js 的 Windows 终端）：

```bash
cd stock-project
npm ci
npm run dev
```

源码包解压后的顶层目录名为 stock-project；已有工作目录时在该目录运行命令即可。干净副本已按锁文件验证安装、553 项检查及生产入口；本机使用现有 npm 缓存时，安装约 4.83 秒、完整检查约 25.45 秒。首次下载依赖所需时间取决于网络，不能保证所有机器都在同一时限完成。

打开 [注册页面](http://localhost:5173/register)，创建账户后自动进入工作台。已有账户可打开 [登录页面](http://localhost:5173/login)。

后端健康检查：[GET /api/health](http://localhost:3000/api/health)。开发命令先构建共享包，再同时启动前后端；Ctrl+C 结束两个进程。修改共享契约后重启开发命令。

Vite 将 /api 和 /ws 代理到后端；WebSocket 使用同源 Cookie 鉴权，顶栏显示实时连接状态。前端固定使用 5173，端口占用时会明确报错。

## 配置

默认无需环境文件。需要更改配置时，将根目录 .env.example 复制为 .env。

| 配置                  | 默认值    | 说明                                               |
| --------------------- | --------- | -------------------------------------------------- |
| PORT                  | 3000      | 后端端口，前端代理同步读取                         |
| HOST                  | 127.0.0.1 | 后端监听地址                                       |
| SESSION_TTL_MS        | 86400000  | 会话有效期，毫秒                                   |
| ENABLE_DEMO_LIQUIDITY | true      | 设置 false 时启动为空订单簿，不提交种子挂单        |
| COOKIE_SECURE         | false     | 浏览器通过 HTTPS 访问时设置为 true                 |
| ALLOWED_ORIGINS       | 自动生成  | 默认允许 localhost、127.0.0.1 的 5173 与 PORT 来源 |

指定 ALLOWED_ORIGINS 时使用逗号分隔的完整来源，例如 https://stock.example；不支持通配符、路径或空值。注册、登录、退出及下单的 POST 请求，以及 WebSocket 握手，必须携带允许的 Origin；浏览器会自动设置。注册、登录和下单只接受 JSON，退出无需请求体。不支持的请求字符集或内容编码返回 415。

## 构建与生产入口

```bash
npm run build
npm start
```

打开 [应用](http://localhost:3000)。构建顺序为共享包、前端、后端，随后由 Express 提供页面、API 和同端口 WebSocket，无需运行 Vite。静态路径相对于模块定位，不依赖启动目录；未知 API、缺失静态资源返回 JSON 404，页面路由交给 Vue Router。

## Docker 启动（选做加分项）

已提供多阶段 Dockerfile 和 docker-compose.yml，前后端由同一个容器、同一端口提供服务。需要先启动 Docker Engine / Docker Desktop；Windows 可直接在项目目录使用 PowerShell，WSL 内运行则需已配置可用的 Docker 引擎或 Desktop 集成。本次实际使用 Windows Docker CLI 验收：

```bash
docker compose up --build
```

打开 [容器应用](http://localhost:3000)。若本地开发后端已经占用 3000，可以改用 4350：

```bash
APP_PORT=4350 docker compose up --build
```

PowerShell 使用 `$env:APP_PORT='4350'` 后运行 `docker compose up --build`。停止可按 Ctrl+C，清理本项目容器执行 `docker compose down`；内存业务数据随容器进程结束清空。

容器固定监听 0.0.0.0:3000，APP_PORT 只改变宿主机映射；同源允许列表随宿主端口生成。通过自定义域名或 HTTPS 访问时，设置完整 ALLOWED_ORIGINS，并按实际 HTTPS 情况设置 COOKIE_SECURE=true。根目录 .env 不会打入镜像，Compose 只读取显式列出的配置。

本次已验证默认端口、自定义端口和 HTTPS 的 Compose 配置解析；实际镜像构建、容器健康检查及双用户交易验收通过。容器使用 Node 22，以非 root 用户直接运行后端，提供前端静态页面、API 和 WebSocket。完整运行记录见[交付清单](docs/交付验收与清单.md)。

## 功能验收

以下流程从默认流动性开启的新服务开始，使用普通窗口与无痕窗口隔离 Cookie：

1. 分别注册 alice、bravo，确认各有 100 万虚拟币且暂无持仓。
2. alice 选择 SIM001，按最佳卖价 10.01 买入 100 股，确认“全部成交”、持仓 100、可用资金 998,999.00。
3. alice 切换卖出，以 11.01 提交 60 股，确认“已挂单”，持仓中冻结 60 股。
4. bravo 以 11.01 买入 1,000 股：先吃掉系统剩余 900 股，再撮合 alice 的 60 股，显示“部分成交”960/1,000，冻结资金 440.40。
5. alice 无需操作即可看到可用资金变为 999,659.60、剩余 40 股、卖单全部成交；以 11.01 卖出这 40 股，确认清仓且资金为 1,000,100.00。
6. bravo 无需刷新即可看到买单全部成交、持仓 1,000 股、冻结资金归零、可用资金 989,890.00。
7. 在“我的委托”筛选已成交，在“我的成交”和“市场成交”核对记录；市场视图不显示用户身份或买卖方向。
8. 刷新浏览器，确认登录与资产恢复；退出 alice，确认 bravo 的独立会话仍有效。重新登录 alice 不会重复发放资金。
9. 输入多于两位小数的价格、小数股数、超过可用资金 / 持仓的委托，确认表单阻止提交且资产不变。
10. 在开发者工具切换离线，等待断线提示（静默断网最迟约 15 秒检测）；确认资产和输入保留、下单暂停。恢复网络后自动重连，或点击“重新连接”，等待完整快照后继续交易。
11. 重启后端，确认旧身份失效并返回登录，数据清空。

下单请求超时或返回 5xx 时，页面显示原股票、方向、限价和数量，并暂停新下单。恢复连接后点击“重试并确认此委托”：如果原委托已受理，返回该订单当前状态；如果尚未受理，本次会提交。即使账户已经通过实时推送更新，也须确认原请求后才能继续。

原请求会在发送前写入当前标签页的 sessionStorage，刷新后仅恢复待确认提示，不自动 POST。同一用户重新登录可恢复，同一页面切换用户或服务重启后不会混用。关闭标签页、清除浏览器存储或换设备后不保证恢复该请求标识，请先核对历史委托；新请求标识代表另一笔委托。浏览器存储不可用时暂停下单；请通过 localhost 或 HTTPS 访问，以使用安全的请求标识生成能力。详情见 [T07 幂等与稳定性验收](docs/幂等与稳定性实现验收.md)。

系统额外初始化一个不可登录的 system 账户，现金同样为 100 万，每只股票持有 10,000 股。默认启动通过撮合服务为每只股票提交 1,000 股种子买单和卖单，价格分别为初始价减 1 分和加 1 分；库存或挂单耗尽后不会自动补充。设置 ENABLE_DEMO_LIQUIDITY=false 后重启，可关闭种子挂单；系统初始库存仍保留。直接创建测试内存时订单簿保持为空。

撮合核心可单独验收：

```bash
npm test -- apps/server/src/tests/trading
```

交易接口包括 `POST /api/orders`、`GET /api/me/orders`、`GET /api/me/trades` 和 `GET /api/trades`。下单必须包含 UUID 格式的 clientOrderId，以及 symbol、side、priceCents、quantity；userId 只取自服务端会话。首次成功返回 201，同用户同标识同参数重放返回 200，标识相同但参数不同返回 409 / IDEMPOTENCY_CONFLICT。查询默认 50 条、最多 100 条，使用服务端序号游标。基础接口验收见 [交易 API 验收记录](docs/交易API实现验收.md)，当前幂等契约以 [T07 验收文档](docs/幂等与稳定性实现验收.md)为准。

## 工程组织与架构决策

```text
apps/client/       登录注册、交易工作台、账户/行情/交易状态、WebSocket 与组件测试
apps/server/       内存存储、身份/会话、撮合与结算、行情定时器、实时推送、接口与测试
packages/shared/   公开 DTO、账户快照、事件契约、错误码和股票常量
```

1. **单进程内存维护唯一状态。** 用户、订单簿、成交及幂等索引共享同一份内存，HTTP 和 WebSocket 读取同一状态；有限系统种子挂单帮助空持仓用户完成首笔交易。重启清空，不支持直接多副本运行。
2. **整数金额与同步原子结算。** 价格和现金按分保存，先预演价格 / 时间优先的撮合，在独立草稿中冻结与结算，资金、持仓与守恒校验通过后一次提交。提交过程无 await，前端不提前改写资产。
3. **HTTP 命令与版本化推送配合。** HTTP 下单按用户和请求标识幂等，超时重试返回原订单；WebSocket 推送完整可见快照，客户端按身份、服务实例及分域版本应用，断线取新快照，旧响应不能覆盖新状态。
